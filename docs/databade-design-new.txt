1. Comprehensive ER Diagram Design

1.1 Entity Identification and Analysis

Based on the functional requirements and user stories from Activities 2 and 3, the following 12 entities have been identified and implemented in the Emergency Dispatch System:

Primary Entities (Current Backend Implementation):
- User: System users with role-based access (Call Takers, Dispatchers, Field Crews, etc.)
- Incident: Emergency incidents logged through various channels (embeds location data)
- Vehicle: Emergency vehicles (ambulances, fire engines) available for dispatch
- Station: Emergency service stations and facilities
- Crew: Field personnel assigned to vehicles and shifts
- Shift: Work shifts with staffing requirements and schedules
- EquipmentChecklistTemplate: Standardized checklists for vehicle types
- EquipmentCheck: Individual equipment inspection records
- Assignment: Resource assignments to incidents
- Communication: SMS/push notification history and delivery tracking
- Report: Post-incident reports and analytics
- AuditLog: System audit trail for compliance

Design Decision: Location data is embedded within Incident, Vehicle, Station, and Crew entities for optimal performance in emergency scenarios. Equipment data is managed through EquipmentCheck and EquipmentChecklistTemplate models with embedded equipment arrays.

2.2 First Normal Form (1NF) - Achieving Atomicity

Objective: Eliminate repeating groups and ensure all attributes contain atomic values.

Rules Applied:
1. Each table cell contains only one value
2. No repeating groups of columns
3. Arrays converted to separate rows or tables
4. Embedded objects properly separated

Transformation Process:

1. Extract repeating groups into separate entities
2. Flatten embedded objects while maintaining relationships
3. Ensure each column contains atomic values
4. Create junction tables for many-to-many relationships

2.3 Second Normal Form (2NF) - Eliminating Partial Dependencies

1. Must be in 1NF
2. All non-key attributes must be fully functionally dependent on the primary key
3. If composite primary key exists, non-key attributes cannot depend on only part of it
4. Separate tables created for partially dependent attributes

3.5 Views for Common Queries

-- Active Incidents View
CREATE VIEW ActiveIncidents AS
SELECT 
    i.incident_id,
    i.incident_string_id,
    i.incident_type,
    i.severity,
    i.status,
    i.location_address,
    i.location_city,
    p.province_name,
    u.first_name AS logged_by_name,
    d.first_name AS dispatcher_name,
    i.created_at
FROM Incident_3NF i
JOIN Province_3NF p ON i.province_id = p.province_id
JOIN User_3NF u ON i.logged_by_user_id = u.user_id
LEFT JOIN User_3NF d ON i.assigned_dispatcher_id = d.user_id
WHERE i.status IN ('pending', 'assigned', 'en_route', 'on_scene');

-- Available Resources View
CREATE VIEW AvailableResources AS
SELECT 
    v.vehicle_id,
    v.plate_number,
    vt.type_name AS vehicle_type,
    v.current_status,
    s.station_name,
    COUNT(vc.crew_id) AS crew_count
FROM Vehicle_3NF v
JOIN VehicleType_3NF vt ON v.vehicle_type_id = vt.vehicle_type_id
LEFT JOIN Station_3NF s ON v.current_station_id = s.station_id
LEFT JOIN VehicleCrew_3NF vc ON v.vehicle_id = vc.vehicle_id
WHERE v.operational_status = 'active' 
AND v.current_status = 'available'
GROUP BY v.vehicle_id, v.plate_number, vt.type_name, v.current_status, s.station_name;

-- Current Assignments View
CREATE VIEW CurrentAssignments AS
SELECT 
    a.assignment_id,
    i.incident_string_id,
    i.incident_type,
    i.severity,
    v.plate_number,
    vt.type_name AS vehicle_type,
    CONCAT(c.first_name, ' ', c.last_name) AS primary_crew,
    a.response_status,
    a.priority,
    a.assigned_at
FROM Assignment_3NF a
JOIN Incident_3NF i ON a.incident_id = i.incident_id
JOIN Vehicle_3NF v ON a.vehicle_id = v.vehicle_id
JOIN VehicleType_3NF vt ON v.vehicle_type_id = vt.vehicle_type_id
JOIN Crew_3NF c ON a.primary_crew_id = c.crew_id
WHERE a.response_status IN ('assigned', 'accepted', 'en_route', 'on_scene');

-- Crew Availability View
CREATE VIEW CrewAvailability AS
SELECT 
    c.crew_id,
    c.employee_id,
    CONCAT(c.first_name, ' ', c.last_name) AS crew_name,
    cr.role_name,
    c.certification_level,
    c.availability_status,
    s.shift_name,
    v.plate_number AS assigned_vehicle
FROM Crew_3NF c
JOIN CrewRole_3NF cr ON c.crew_role_id = cr.crew_role_id
LEFT JOIN Shift_3NF s ON c.shift_id = s.shift_id
LEFT JOIN Vehicle_3NF v ON c.assigned_vehicle_id = v.vehicle_id
WHERE c.is_active = TRUE;

-- Data Integrity Constraints
ALTER TABLE User_3NF ADD CONSTRAINT chk_phone_format 
CHECK (phone REGEXP '^\\+94[0-9]{9}$');

ALTER TABLE Incident_3NF ADD CONSTRAINT chk_coordinates_sri_lanka
CHECK (location_lat BETWEEN 5.9 AND 9.9 AND location_lng BETWEEN 79.6 AND 81.9);

ALTER TABLE Vehicle_3NF ADD CONSTRAINT chk_plate_sri_lanka
CHECK (plate_number REGEXP '^[A-Z]{2,3}-[0-9]{4}$|^[0-9]{2,3}-[0-9]{4}$');

ALTER TABLE EquipmentCheck_3NF ADD CONSTRAINT chk_duration_positive
CHECK (duration >= 0);

ALTER TABLE Assignment_3NF ADD CONSTRAINT chk_times_logical
CHECK (accepted_at >= assigned_at AND en_route_at >= accepted_at AND 
       on_scene_at >= en_route_at AND completed_at >= on_scene_at);
