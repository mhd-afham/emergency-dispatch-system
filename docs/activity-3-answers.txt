5. Kanban Board Structure

Kanban Board Design:
Tool Recommendation: Trello (Free, user-friendly, suitable for academic project)

Board Columns:
1. Product Backlog - All user stories prioritized by MoSCoW
2. Sprint Backlog - Stories committed for current sprint
3. To Do - Sprint tasks ready to start
4. In Progress - Stories being actively developed (WIP Limit: 5)
5. Code Review - Completed code awaiting peer review (WIP Limit: 3)
6. Testing - Stories in testing phase (WIP Limit: 2)
7. Done - Completed and validated stories

Work in Progress (WIP) Limits:
In Progress: 5 (one per team member maximum)
Code Review: 3 (prevent review bottlenecks)
Testing: 2 (ensure quality focus)

Card Structure:
Each Trello card contains:
Title: User Story ID and description
Labels: Priority (Must/Should/Could), Team Member, Epic
Checklist: Acceptance criteria items
Due Date: Sprint end date
Attachments: Relevant documents, mockups
Comments: Progress updates, blockers

Labels System:
Priority: Red (Must Have), Orange (Should Have), Yellow (Could Have)
Members: Green (Afham), Blue (De Silva), Purple (Spencer), Pink (Nawanjana), Gray (Udayanga)
Type: Backend, Frontend, Mobile, Database, Integration
